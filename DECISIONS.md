# Decision notes

Substitutions and defaults from PRD v3.0 §10 / §14. Recorded as required by §13.2.

| Concern | PRD default | Choice | Note |
| --- | --- | --- | --- |
| Web | Next.js + Tailwind | Next.js 15 App Router, Tailwind 3 | SSR public pages |
| API | Node REST + OpenAPI | Hono on Node | Same contract |
| Queue | Redis-backed | BullMQ | Stage retry + DLQ |
| Storage | S3-compatible | AWS SDK + MinIO locally; production currently uses `STORAGE_DRIVER=fs` on the Fly volume `okm_data` | Single-machine API with the worker inline (`INLINE_WORKER=true`, no Redis). Move to S3/R2 before running more than one machine. |
| Retention | Delete originals on schedule | Hourly job in the API process: bytes and previews deleted at `retain_until` (signed-in 30 days, anonymous 1 day); anonymous analyses purged after 24 hours. Evidence and hashes kept. | Runs only while the machine is up (`auto_stop_machines`); the first run is 60 s after boot. Provenance thumbnails are separate per-record copies, so retention never breaks a public record. |
| Metadata | ExifTool | ExifTool when present; `exifr` fallback in local/dev | Producer version recorded |
| C2PA | Official SDK | `@contentauth/c2pa-node` `Reader` against C2PA 2.3; Trust List via `verifyTrust`; five AN-25 states from `validation_status`. The worker downloads the official C2PA trust list and the frozen interim list into `C2PA_TRUST_DIR` (Fly: `/data/c2pa-trust` on `okm_data`) and passes that local PEM path. `c2pa-node` does not fetch trust-anchor URLs. A signer that is only untrusted is `valid_signer_not_recognised`, not a broken binding. Create still does not embed C2PA (PR-7) until a Trust List CA certificate. API/worker Node 22 for the native module. | Never a custom parser |
| Signing | Cloud KMS | `KmsSigner` interface: AWS KMS (`AWS_KMS_KEY_ID` + `SIGNING_PUBLIC_KEY_PEM`) or ECDSA P-256 PEM | Production signs with AWS KMS key `alias/oyokometa-signing` (eu-west-1, ECC_NIST_P256), kid `okm-kms-1`, defined in `infra/aws/signing-key.yaml` (stack `oyokometa-signing`). The API authenticates as IAM user `oyokometa-signer`, which may only `kms:Sign`, `kms:GetPublicKey` and `kms:DescribeKey` on that key. Public key: `infra/aws/signing-public.pem`. The earlier env key `okm-fly-1` is published as retired via `SIGNING_RETIRED_KEYS_JSON`. Without KMS, production refuses to sign unless `SIGNING_ALLOW_ENV_KEY=true`. To rotate: create a new key, publish the current one as retired (`pnpm --filter @oyokometa/api signing:retired-key`, or take its public JWK from `/.well-known/oyokometa-keys.json`), then set the new `AWS_KMS_KEY_ID`, `SIGNING_PUBLIC_KEY_PEM` and `SIGNING_KEY_ID`. Records verify against the key they name, so older records stay valid. |
| TSA | RFC 3161 | DigiCert (`TSA_URL=http://timestamp.digicert.com`). Request carries a SHA-256 imprint, nonce and `certReq`; the reply must be granted, match the imprint and nonce, and its CMS signature must verify (pkijs). The TimeStampToken DER is stored. | Production never falls back to the platform clock: no verified token, no record, and the credit hold is released. TSA certificate chain is not yet validated against a pinned root. Development without `TSA_URL` records a labelled platform-clock assertion. |
| Payments | Paystack/Flutterwave + Stripe | Direct bank transfer with unique `OKM-` narration code, plus Bachs hosted checkout. **I have sent the transfer** only moves a bank payment to `awaiting_match`. An admin or finance user confirms that deposit to grant credits. Bachs grants credits only from a signed `collection.succeeded` webhook (`SUCCEEDED` or `OVERPAID`). `refund.paid` and a lost dispute reverse them. | Amount and pack come from `credit_products`. Bank transfer uses the naira price. Bachs uses `usd_price_minor`, with the naira price as a locked NGN option. Credits granted once per payment id, never from a client redirect. `BACHS_API_KEY` and `BACHS_WEBHOOK_SECRET` live in the environment. |
| Paid actions | Price + balance + confirm | Every paid action (Deep Analysis, upgrade, report, registration, capture) shows price, balance and balance after, and the client must echo `expected_credits`. If it differs from the current price the API returns `409 price_changed` and charges nothing. | Prices with a future `effective_from` are ignored until they take effect. |
| Malware | Scan then decode | ClamAV (`clamd` INSTREAM) on a private Fly app `oyokometa-clamav` (`infra/fly/clamav.toml`). Production fails closed: no scanner or a scanner error stops the analysis with `service_unavailable` and no charge. | Every scan result (clean, flagged, skipped) is stored as a raw output. `MALWARE_SCAN_REQUIRED=false` is the only way to skip in production. |
| Adult content | Attestation only | Hive visual moderation (`content-policy@1.0.0`) on the decoded JPEG, before a preview is stored. Analyze, Create, Capture, and Verify all use that path. Refuse when `general_nsfw`, `yes_sexual_activity`, or `yes_realistic_nsfw` is 0.9 or higher. Suggestive classes are not refused. A missing key, error, timeout, or rate limit fails closed, releases a Deep Analysis hold, and stores no preview. A refusal deletes the original. The stored decision is `accepted` or `refused` under the neutral producer name. The vendor name stays in this note and the privacy notice. | `HIVE_API_KEY` is the V3 secret. The playground allowance is about 100 requests a day until Hive raises it. This is not a child-sexual-abuse control. |
| Capture requests | No live capture | A signed-in account creates a one-time link at `/capture`. The recipient opens `/c/{token}` and takes one photo through the browser camera. The page fits the longer side to 1600 pixels and sends that JPEG. Oyokometa hashes those bytes on receipt, runs the malware scan and the adult check, and signs a `platform_signed_record` with mode `capture`. Verified means the link was unused, the bytes arrived in that open session, the hash was taken then, and the signature still matches. The public line is "This photo was received through an Oyokometa capture session at {time}. The file matches the signed record." The sub-line is "This confirms the file is unchanged since receipt. It does not confirm that the camera was physical, or that the scene is what it appears to be." A client assertion that the camera was live, the browser user agent, and a consented device location are Declared and shown separately. Creating the link holds `capture_request` credits (25). The client must echo `expected_credits`. The hold settles when the record is signed and is released if the link expires, is cancelled, the account is deleted, or the file is refused. A scanner or adult-check outage leaves the link open and the hold in place. No C2PA manifest is embedded. | The link token and the session nonce are stored only as hashes. A gallery upload is not offered. That is a product control: a virtual camera can still feed the browser. The record is private to the account that created the link. When the owner opens the record, Oyokometa may ask OpenStreetMap Nominatim to name the area around the reported coordinates. The place name is cached, is not written into the signed payload, and does not measure where the camera was pointed. A reading coarser than 80 m is named at area level, without a road or house number. The signed record also stores the browser string received with the upload, and any camera name, front or back facing, device model, and platform the page reports. Those fields are what the browser reported. They are not a hardware attestation. A capture made before the camera name was collected still shows the browser string when one was stored. Screen-recapture scoring and a challenge code are later and do not upgrade this claim. |
| Civic Evidence | No case workflow | Civic Evidence is a case layer on the existing Capture and provenance records. Ordinary `/capture` still holds 25 credits. A capture link with `capture_requests.case_id` set is free and does not hold credits. Roles `reviewer` and `editor` are values of `users.role`. A reviewer reads only assigned cases. An editor reads cases that have reached a proposed finding, editorial review, publication, reopening, or withdrawal. An admin can assign a reviewer and cannot read the claim or the contributor identity by that role alone. Contributor identity stays hidden from staff while `identity_restricted` is true. `trust-and-safety` can read a sensitive or restricted case and can refer or close it, without the contributor identity. A checked restricted-handling request sets `sensitivity_level` to `restricted` and `restricted_handling` to true. Then only the contributor, an assigned reviewer, an assigned editor, and trust-and-safety can open the case. An unassigned editor cannot open it from the editorial queue. That request is not a promise of absolute anonymity. Publishing, returning an editorial review, and reopening require `editor`. Case audit rows are append-only. Public intake is `/civic`: three forms, a private receipt, and an optional still image or http(s) link. There is no video-file upload; a claim about a video is submitted with the post link and, if available, a still frame. `claim_text` is the circulating claim being assessed. `contributor_explanation` is the submitter's own comment and is stored on the case, not as a source. It is not on the public allowlist. A result-sheet case also stores `specific_check`, the concrete question for triage, separately from the general claim. A reviewer assigned to a case, or an editor who can read it, creates a one-time capture link at `/civic/desk`. That link sets `capture_requests.case_id`, does not hold credits, and the recipient consents before the camera opens. A completed photo keeps the existing signed capture record and adds a `civic_evidence_items` row that points at that record and its stored file. The signed payload is not rewritten. Closed, withdrawn, and referred cases cannot request a new link. A public case page at `/civic/p/{reference}` is generated only from an editor-approved `civic_case_versions` payload. The payload is an allowlist: claim, assessment, conclusion, rationale, evidence summary, limitations, methodology, broad location, sources, and Verified/Detected/Inferred/Declared lines. Contributor identity, exact coordinates, user agent, and capture tokens stay off that page. A correction inserts a new immutable version and keeps the earlier one. An unpublished case 404s like a missing id. Public appeals write `civic_appeals`, not provenance disputes. Hourly image retention does not delete a file attached to a civic case. Civic rows stay until a recorded editorial or legal decision. They are not auto-deleted. Public text is stored as plain text. Markup is stripped. Guessing a private reference returns the same not-found as a missing id. Result-sheet OCR stays off. | Tables are `civic_cases`, `civic_evidence_items`, `civic_sources`, `civic_reviews`, `civic_evidence_assessments`, `civic_case_versions`, `civic_audit_events`, and `civic_appeals`, plus nullable `capture_requests.case_id`. Row level security is on and has no policies. The API uses `DATABASE_URL`. A case reference is `OKM-E` plus 8 characters. There is no video upload and no new analytics or OCR provider. |
| Customer feedback | No public contact form | `/contact` stores a name, email, and message in `feedback_messages`. Public visitors cannot read messages. A confirmation email uses Resend when it is configured; the page says an email was sent only when delivery succeeds. The team notice goes to `ADMIN_EMAIL` and includes the message. Five messages an hour per IP. Kept until deleted from the database. | Distinct from `/request-solution`, which is for a scoped engagement. |
| Enterprise intake | Contact form later | `/about`, `/services`, and `/request-solution` describe a solutions practice beside the self-service product. A request is stored in `client_requests`, with status changes in `client_request_events`. Public visitors cannot read requests. Admin, support, finance, and trust-and-safety can review them at `/admin`. No customer file upload on the form. Requests are kept until an admin archives them. Confirmation email uses Resend when it is configured; the page says an email was sent only when delivery succeeds. The team notice goes to `ADMIN_EMAIL` and omits the problem text. | Service definitions live in `packages/config/src/solutions.ts`. Budget bands are qualification ranges, not prices. |
| Account deletion | Self-service | Account page: password, or an emailed link for link-only accounts, plus typing DELETE. Removes images, analyses, reports and share links; withdraws provenance records with a signed event; anonymises the user row; redacts audit rows naming the email. | Ledger and payment rows stay for accounting against the anonymised user. Unused credits are forfeited. |
| Audit log | Append-only | Trigger blocks UPDATE, DELETE and TRUNCATE on `audit_log` (migration `0006_phase0`). The only exception is redaction during account erasure, inside a transaction that sets `oyokometa.audit_redaction`. | |

| AI labels | Off until §12 gate | `config.ai_labels_enabled` default false. Detector scores are stored and are not shown, and they do not change a finding until the gate is recorded. | AN-32 |
| AI detectors | One on Quick Scan, two on Deep Analysis | Quick Scan and Deep Analysis call a private Fly app (`oyokometa-detector`, `infra/detector/fly.toml`) running Community Forensics ViT-Small (`adapter-a`, ONNX v1.1). Deep Analysis also calls Sightengine `genai` and `deepfake` in one request (`adapter-b`), and Reality Defender's image ensemble (`adapter-c`) when `REALITYDEFENDER_API_KEY` is set. The ensemble is one signal: 56–100 strong, 45–55 weak, and a lower score adds no camera-origin evidence. `NOT_APPLICABLE` is stored as a limit. A Sightengine timeout or error releases the Deep Analysis hold and marks AI analysis unavailable. A Reality Defender failure does not. The vendor name stays in this note and the privacy notice, not in analysis output. Social links are out of scope. | No watermark detector is available. Labels stay off until the §12 corpus passes. Heatmaps are not stored yet. Sightengine credentials are `SIGHTENGINE_API_USER` and `SIGHTENGINE_API_SECRET`. |
